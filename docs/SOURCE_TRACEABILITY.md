# Source Traceability

## Purpose

Traceability connects a source detail to a game element, a design reason, and a guardrail.

## Traceability chain

Use this chain:

```text
Source record -> Extracted detail -> Design tension -> Original transformation -> Review guardrail -> Canonical artifact
```

## Required fields

Each source-derived design change records:

- A source identifier.
- A chapter or section.
- A concise source note.
- The extracted tension or function.
- The original game transformation.
- The canonical artifact.
- The required review domains.
- The rights class.

## Example

| Field | Entry |
|---|---|
| Source identifier | `EDU-002` |
| Source section | Chapters 1 through 7 |
| Source detail | Family labor combines skill, danger, care, and authority. |
| Design tension | Competence can increase dependence and risk. |
| Original transformation | Repair tasks change safety, trust, and future access. |
| Canonical artifact | Gameplay Systems Bible |
| Guardrail | The game does not reward preventable harm. |
| Rights class | Composite influence |

## Conflict handling

Record conflicting source memories as separate claims.

Do not silently combine them into one fact.

The game can transform the conflict into an evidence or memory system.
