# Governance

## Decision owner

Hubert Williams owns the project vision, scope, and final concept decisions.

## Review domains

A change can require one or more review domains:

- Game design.
- Narrative design.
- Source fidelity.
- Faith representation.
- Rural-work accuracy.
- Medical and trauma content.
- Accessibility.
- Rights and attribution.

## Canonical artifacts

A file under `packages/` is canonical when its directory README identifies it as canonical.

A preview image does not replace its source deck or spreadsheet.

## Decision records

Use an architecture decision record when a change affects:

- A design principle.
- A major gameplay system.
- A core character arc.
- The source-transformation method.
- The rights boundary.
- The prototype scope.

## Approval rules

The project director approves scope and canon changes.

A domain reviewer approves changes within a required review domain.

No reviewer can approve a rights claim without qualified legal review.

## Conflict rule

Record unresolved conflicts in the pull request.

Do not hide a source conflict, design trade-off, or review disagreement inside revised prose.
